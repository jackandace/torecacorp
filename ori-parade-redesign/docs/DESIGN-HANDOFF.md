# オリパレード UIデザイン リニューアル

既存サイト: https://ori-parade-frontend.vercel.app/
調査日: 2026-09-07

## デザインの方向性

「毎日が、お宝パレード。」
オリジナルのキャラクターとイラスト、オレンジのブランドカラーを引き継ぎ、遊び心のある配色と読みやすい構成を両立します。大きなヒーローだけの紹介サイトではなく、トップからオリパを選び、詳細を確認できるサービス画面です。

- オレンジ: 主操作、コイン、アクティブ状態。
- イエロー: ウェルカム、ログインボーナス、ランク特典。
- パープル: 合成、チケット、ステップアップ。
- ミント: 選択型ガチャ、補助的な体験。
- 本文はダークインク、背景はほぼ白。装飾色と情報色を分けます。
- 既存の画像ロゴ・ガチャ画像・カード画像をローカルの assets に収録しています。

## PC / SP

- PC: 最大1240px。ヘッダーに主要5項目のナビ。オリパは3列、詳細は画像＋右側の操作パネル、マイページは2列。
- タブレット: 850px以下で下部ナビへ切り替え。商品は2〜3列に調整。
- SP: 左右16px余白。主要操作44px以上を基本とし、オリパは2列。フォームは1列。詳細の購入パネルは画像直後、獲得商品の操作パネルは一覧の後へ。
- 固定ナビにはセーフエリア余白を確保。フォーカス表示、キーボード操作、フォームラベル、reduced-motionに対応。

## コンポーネント構成

- `app/shared.tsx`: SiteHeader / SiteFooter / PageHeading / Coin / Empty / PreviewDialog。
- `app/parade.tsx`: トップ、カテゴリー絞り込み、並び替え、オリパ一覧。
- `app/screens.tsx`: 各ページの画面コンポーネント。認証と設定フォームを共通化。
- `app/globals.css`: カラー・文字サイズ・余白・角丸・レスポンシブ指定。
- `components/ui`: 導入済みのアクセシブルなダイアログ、タブ、チェックボックス、ラジオ、セレクト、プログレス、表。
- `/design-system/`: 色、ボタン、全画面へのリンクをまとめた確認用ページ。

## 動作範囲

これはデザイン実装・検討用の独立したフロントエンドです。本番のソースリポジトリ、認証、決済、抽選、配送、アカウント変更には接続していません。

- 実装済み: 遷移、絞り込み、並び替え、タブ切り替え、商品選択、交換/発送の確認とサンプル状態遷移、レシピ確認、ステップ解放サンプル、ルート選択確認、既読表示、ボーナス受け取り済み表示、フォームの必須・形式・一致・年齢チェック。
- クーポンのプレビューコードは `DEMO`。招待コード `PARADE` は表示用です。
- 残高、履歴、期限、商品状態はサンプルです。実際の住所・メールアドレス・ユーザーIDは成果物に含めていません。
- フォーム入力は送信・永続保存しません。実際の個人情報は入力せず確認してください。
- 合成や発送などの状態変化は、その画面内のみのデモです。ページ再読込でリセットされます。
- メール送信、SMS認証の完了、カード決済、ランダム抽選の実処理は未接続です。完了したと誤認させない文言で案内します。
- WebMCP `filter_oripa_catalog` を対応ブラウザーで登録する処理を実装。入力検証とカテゴリー表示更新に限定します。WebMCP対応の検証コンテキストがないため登録・呼び出しの実機検証は未実施です。

## 元サイトの調査で分かった制約

- MCPでトップ、主要5ページ、オリパ詳細、ステップアップ、2択、ランク、ブースト、チケット、クーポン、配送先、新規登録、ログイン、変更フォームを確認。
- 元サイトの `/purchases/3` はヘッダーとナビ以外のコンテンツが表示されず、決済方法・購入確認は完成案として補完しました。クレジットカードは仮の選択肢です。
- 新規登録の「利用規約」はリンク先がなく、クリックではチェック状態のみが変わりました。正式な本文は取得できていないため、規約ページでその旨を明示しています。規約は創作していません。
- ログイン後にしか到達できない画面、結果の状態別画面、決済側のリダイレクト画面などの全網羅は、元ソースのルート一覧と照合する必要があります。
- 新しいサイトのPC/SP実ブラウザーでの見た目・操作検証は今回未実施です。レスポンシブCSSと型・ビルド・出力ルート/アセットの検査を実施しています。

## 既存サイトへ適用する手順

1. 既存リポジトリのルーティングと全画面一覧を上表に照合する。
2. globals.css のトークンと共通部品を取り込み、既存のデータ取得・認証ロジックを共通レイアウトの内部に保持する。
3. サンプルの products / demoItems / 残高などを既存APIへ接続し、在庫・権限・期限・価格は必ずサーバーの値を使う。
4. 決済・抽選・交換・配送処理の直前確認を接続し、失敗/処理中/完了の状態を実際のAPI応答に連動させる。
5. 規約の正式本文、正しい決済手段、SMSフローを配置する。
6. 実際のPC/SPで最終確認し、デモ表示を外して既存の公開先へ反映する。

この段階で元のVercelサイトの変更・再デプロイは行っていません。
