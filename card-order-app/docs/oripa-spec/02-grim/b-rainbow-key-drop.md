# 02-b. レインボーキー ガチャドロップ機能

| 項目 | 内容 |
|------|------|
| クライアント | GRIM様 |
| 機能ID | 02-b |
| 種別 | 新規機能 |
| ステータス | 仕様確定待ち（ドロップロジックは要承認） |

---

## 1. 目的・背景

**通常コイン消費ガチャ** にて、特殊アイテム **レインボーキー** がランダムでドロップする機能。

- ガチャから排出される **上限レインボーキー数** を設定できる。
- **ハズレ景品（C/D/その他）＞ あたり景品（S/A/B）** を中心に排出され、**救済機能** 的に使いたい。
- もちろん **S賞などでもドロップ** するようにしたい（＝全レアリティ非ゼロ）。→ **ロジックに工夫が必要**。
- **手動で「指定景品当選時にドロップ」** できる拡張性も持たせたい。

**フロント:**
- レインボーキーがドロップしたことを表示する **モーダル** を追加。
- **レインボーキー保有一覧（既存）** に、**排出経路をラベル** として残す。

---

## 2. 設計方針：ドロップロジック（工夫ポイント）

「ハズレ中心だがS賞でも出る」「総数に上限」「手動指定もできる」を両立するため、
ドロップ判定を **3レイヤー** で構成する。判定は **当選景品が確定した後** に行う。

```
┌ レイヤー0: グローバル上限（プール）─────────────────┐
│  このガチャから出せる残りレインボーキー数 > 0 か？        │
│  0 なら以降は一切ドロップしない（在庫切れ）              │
└──────────────────────────────────────────────┘
              │ remaining > 0
              ▼
┌ レイヤー1: 個別景品オーバーライド（手動指定）──────────┐
│  当選景品に「ドロップ設定」があれば最優先で適用          │
│   ・drop_mode = always   → 必ず drop_count 個ドロップ    │
│   ・drop_mode = rate     → 指定確率で drop_count 個      │
│   ・drop_mode = inherit  → レイヤー2へ（既定）           │
└──────────────────────────────────────────────┘
              │ inherit
              ▼
┌ レイヤー2: レアリティ別ドロップ率テーブル ──────────────┐
│  当選景品のレアリティに対応するドロップ率で抽選          │
│   例) D:25%  C:18%  B:8%  A:4%  S:1.5%                  │
│  → 低レア高確率／高レア低確率だが、全レア非ゼロ          │
└──────────────────────────────────────────────┘
```

### なぜこの設計か
- **救済性**: レアリティ別テーブルで低レアの確率を高く設定 → ハズレ中心の排出。
- **S賞でも出る**: 高レアの確率を 0 にしなければ S 賞でもドロップ（工夫＝景品の良し悪しと独立した「追加ドロップ抽選」にする）。
- **総量コントロール**: プール上限で配布総数を制御し、コスト/インフレを防止。
- **拡張性**: 個別景品オーバーライドで「このカードを当てたら必ずキー2個」等の演出/キャンペーンが後付け可能。

> **ポイント**: レインボーキーのドロップは「当たった景品そのもの」ではなく、景品確定後に走る **別レイヤーの追加抽選**。
> これにより「S賞を引いた上にキーも出る」が自然に表現でき、ハズレ救済と矛盾しない。

---

## 3. ドロップ判定の仕様（挙動）

ドロップ判定は **当選景品が確定した後** に、各抽選結果に対して実行する。連続抽選は1枚ずつ順に処理する。判定は前述の **3レイヤー** の順で行う。

- **レイヤー0（プール上限）**:
  - ドロップ機能が無効ならドロップしない。
  - このガチャから出せる残りレインボーキー数が 0 以下なら、以降は一切ドロップしない（在庫切れ）。
- **レイヤー1（個別景品オーバーライド・手動指定）**:
  - 当選景品にドロップ設定があれば最優先で適用する。
  - 「必ずドロップ」設定なら、指定された個数を必ずドロップする。
  - 「確率ドロップ」設定なら、指定された確率で当たった場合に指定個数をドロップする。
  - 「既定（継承）」設定の場合はレイヤー2へ進む。
- **レイヤー2（レアリティ別ドロップ率）**:
  - 当選景品のレアリティに対応するドロップ率で抽選する。レアリティに対応する率が無い場合は「その他」の率を用いる。
  - 当たった場合は、設定された1ドロップあたりの付与数をドロップする。
  - 低レアほど高確率・高レアほど低確率だが、すべてのレアリティで非ゼロにできる。
- **プール残量によるクランプ**:
  - 算出したドロップ数は残りの排出可能数を超えないように丸める（在庫を超えない）。
  - ドロップした分だけ残り排出可能数を減算する。減算は同時実行による超過配布を防ぐため、整合性を保ってアトミックに行う。
- **連続抽選**: 100連等は1枚ずつ判定し、残量を都度減算する。途中で枯渇したら以降は0となる。
- ドロップ数が 0 より大きい場合のみ、キーを付与し、取得経路を記録し、フロントへドロップ情報を返す。

## 4. 管理画面（コンソール）

ガチャ作成・編集画面に「レインボーキードロップ」セクションを追加。

```
┌─ レインボーキードロップ設定 ─────────────────────┐
│ ドロップ機能      [ ●ON / ○OFF ]                    │
│ 排出上限数(プール) [ 100 ]  ※空欄=無制限             │
│ 1ドロップ付与数    [ 1 ]                             │
│                                                    │
│ レアリティ別ドロップ率(%)                            │
│   S [ 1.5 ]  A [ 4 ]  B [ 8 ]  C [ 18 ]  D [ 25 ]    │
│   その他 [ 25 ]                                     │
│   ▷ 低レアほど高確率＝救済。S/Aも0より大きく設定可。   │
│                                                    │
│ ［ 景品別ドロップ指定 ＋追加 ］（任意・手動指定）      │
│   ┌ カード「○○SR」: 必ず 2個ドロップ (always) ─┐    │
│   └ カード「△△UR」: 30%で 1個 (rate) ────────┘    │
└────────────────────────────────────────────┘
```

- 一覧に「残り排出数 / 上限」を表示し、運用中の在庫を把握。
- バリデーション: 率は 0〜100、プール/付与数は 0 以上整数。

## 5. ユーザー画面

### 5-1. ドロップ演出モーダル
抽選結果表示の後、ドロップがあれば被せて表示。

```
┌──────────────────────────────┐
│        🌈  ✨                   │
│   レインボーキーをゲット！         │
│                                │
│        🌈 × 1                   │
│   「幻のSSRオリパ」から排出        │
│                                │
│   保有数: 6 → 7                  │
│   [   確認する   ]               │
└──────────────────────────────┘
```
- 複数枚ドロップ時は合計数を表示。
- 演出（虹のきらめき）はライト/モーション控えめ版も用意（パフォーマンス配慮）。

### 5-2. レインボーキー保有一覧（既存画面の拡張）
各取得履歴に **排出経路ラベル** を表示:
```
🌈 7 個 保有

取得履歴
─────────────────────────────
🌈 +1  幻のSSRオリパ / Dランクから排出     6/13 10:11
🌈 +2  夏祭りオリパ / 指定景品「花火UR」    6/12 21:03   [指定]
🌈 +1  幻のSSRオリパ / Sランクから排出     6/11 18:40
🌈 +5  運営付与（おわび）                  6/10 12:00   [運営]
```
- `source_type` に応じてラベル末尾にバッジ（`[指定]` `[運営]` 等）。

## 6. エラー・整合

| ケース | 挙動 |
|--------|------|
| プール枯渇 | 以降ドロップ0。エラーにはしない（抽選自体は成立） |
| 同時抽選で在庫超過の懸念 | `pool_remaining` を行ロック/CASでアトミック減算 |
| ドロップ後の付与失敗 | 抽選と同一トランザクション。失敗時はロールバック |

---

## 7. テスト観点

- [ ] D/C等 低レア当選で高確率ドロップ、S/A当選でも低確率で非ゼロドロップ
- [ ] プール上限到達後はドロップしない（在庫切れ）
- [ ] 連続抽選で在庫が途中枯渇しても超過配布されない
- [ ] 景品別オーバーライド「必ずドロップ」で必ず指定数ドロップ
- [ ] 景品別オーバーライド「確率ドロップ」で確率通りにドロップ
- [ ] ドロップ時にフロントへ情報が返り、モーダルが表示される
- [ ] 保有一覧に排出経路ラベルが正しく残る（ガチャ名/レアリティ/指定/運営）
- [ ] 02-a 通知（`rainbow_key_drop`）と連携（任意）
