## 1. スコープ

### 1-1. In Scope
- ヘッダーへの通知ベル設置（未読バッジ）。
- 通知ページ（3タブ：あなたへの通知 / チャージ / お知らせ）。
- 通知の自動生成（アクション連携）・手動配信（お知らせ／個別）。
- 未読/既読管理、未読件数算出。
- 保持期間とパージ処理。
- 管理画面：お知らせ配信・個別送信・配信履歴。

### 1-2. Out of Scope（将来拡張）
- Web Push / モバイルプッシュ（フック点のみ用意）。
- 通知タイプ別のユーザーON/OFF設定。
- メールダイジェスト配信。
- リアルタイム配信（WebSocket）。本リリースは **ポーリング/画面遷移時取得** とする。

## 2. 通知分類モデル

通知は3タブに分かれ、データ的には **2系統** に分類される。

| タブ | 系統 | 配信 | 既読単位 |
|------|------|------|---------|
| あなたへの通知 | personal | アクション自動 | 通知1件単位 |
| チャージ | charge | 決済自動 | 通知1件単位 |
| お知らせ | broadcast | 管理手動 | ユーザー×お知らせ |

### 2-1. 通知タイプ一覧

| tab | type | ラベル | 遷移先 既定 | 自動/手動 |
|-----|------|--------|----------------|-----------|
| personal | `shipping` | 配送通知 | 配送詳細 | 自動 |
| personal | `point_granted` | ポイント付与 | ウォレット | 自動 |
| personal | `rank_up` | ランクアップ | ランク | 自動 |
| personal | `invite_bonus` | 招待特典付与 | ウォレット | 自動 |
| personal | `coin_expiry` | コイン有効期限 ※ | ウォレット | 自動(バッチ) |
| personal | `individual` | 個別のお知らせ | URL/なし | 手動 |
| charge | `charge_complete` | 課金時の詳細内容 | 購入詳細 | 自動 |
| broadcast | `campaign` | キャンペーン情報 | 詳細ページ | 手動 |
| broadcast | `event` | イベント情報 | 詳細ページ | 手動 |
| broadcast | `correction` | 誤表記・訂正 | 詳細ページ | 手動 |
| broadcast | `other` | その他お知らせ | 詳細ページ | 手動 |

> ※ `coin_expiry` はGRIMのコインに有効期限がある場合のみ有効化（§9-D）。
> タイプはコード側の定義（ラベル/アイコン/遷移先の既定）で管理し、追加時の作業を最小化することを目標とする。

| ID | 要件 | 優先度 |
|----|------|--------|
| FR-01 | ヘッダー右上に通知ベルを表示する（全ページ共通＝マイページ上部含む） | 必須 |
| FR-02 | 未読件数 > 0 のとき、ベルに赤丸バッジを表示する（件数表示、100件以上は `99+`） | 必須 |
| FR-03 | ベル押下で通知ページに遷移し、既定タブ「あなたへの通知」を表示する | 必須 |
| FR-04 | 通知ページ上部に3タブを表示し、タブ切替で対応リストを表示する | 必須 |
| FR-05 | 各リストは新しい順。1行に「日時（薄字）」＋「本文」を表示する | 必須 |
| FR-06 | お知らせタブの各行は右端に `>` を表示し、押下で詳細ページに遷移する | 必須 |
| FR-07 | 各リストはページネーション（1ページ20件）で表示する | 必須 |
| FR-08 | 通知行タップで既読化し、種別に応じた画面へ遷移する | 必須 |
| FR-09 | 各タブに「すべて既読にする」操作を提供する | 必須 |
| FR-10 | 各アクション（発送/ポイント付与/ランクアップ/招待成立/決済完了）発生時に対応通知を自動生成する | 必須 |
| FR-11 | ランクアップ通知の本文に「新ランク・獲得ポイント・還元率(%)」を差し込む | 必須 |
| FR-12 | 管理画面からお知らせを配信できる（即時/予約、詳細本文、表示終了） | 必須 |
| FR-13 | 管理画面から個別のお知らせ（任意テキスト）を個別ユーザー/セグメントに送信できる | 必須 |
| FR-13b | セグメントを **条件で絞り込める**：①ガチャIDで絞り込み（指定ガチャ利用者）②直近ログインN日以内（アクティブ）。複数条件はAND、既存ランク/属性とも組合せ可、送信前に対象人数の概算を表示 | 必須 |
| FR-14 | 管理画面で配信履歴（配信数・開封率）を確認できる | 推奨 |
| FR-15 | personal/charge通知は作成から31日経過で自動削除する | 必須 |
| FR-16 | 自分宛て以外のpersonal/charge通知は取得・閲覧できない（権限制御） | 必須 |
| FR-17 | コイン有効期限通知をバッチで生成する（有効化時のみ） | 条件付 |

## 4. 通知生成（自動送信）

### 4-1. 自動送信の方針
- 各業務処理の **成功確定後** に通知を生成する（業務処理本体とは疎結合とし、通知生成が失敗しても業務処理本体には影響させずログに記録する）。
- 本文はサーバ側のテンプレートに値を差し込んで生成する（将来の多言語化を見据えてテンプレートの定義化を推奨）。

### 4-2. トリガ対応（どのアクションでどの通知が出るか）
| アクション | 出す通知 | 本文に差し込む情報 |
|-----------|----------|----------|
| 発送ステータス→発送済 | あなたへの通知（配送通知） | 追跡番号・配送業者・注文番号 |
| ポイント付与確定 | あなたへの通知（ポイント付与） | 付与ポイント数・理由 |
| ランク昇格確定 | あなたへの通知（ランクアップ） | 旧ランク・新ランク・獲得ポイント・還元率（前/後） |
| 招待成立・特典付与 | あなたへの通知（招待特典付与） | 特典内容・招待した相手 |
| 決済完了（確定） | チャージ（課金時の詳細内容） | 金額・コイン数・ランクポイント・決済手段・決済ID |
| コイン期限前日/当日（バッチ） | あなたへの通知（コイン有効期限） | 対象コイン数・有効期限 |

### 4-3. ランクアップ本文生成（FR-11）
ランク設定マスタ（ランク別の付与ポイント・還元率）を参照し、本文に「新ランクへの昇格」「獲得ランクポイント」「ポイント還元率の変化（昇格前% → 昇格後%）」を差し込んで生成する。

### 4-4. 反映の流れ（発送通知の例）
1. 管理/物流が発送ステータスを更新し、出荷情報が確定する。
2. 確定後、対象ユーザー向けに配送通知を生成する。
3. ユーザーがアプリ起動/通知ページを開いた際に、未読件数・一覧として反映される。

## 5. 未読件数・保持期間ロジック

### 5-1. 未読件数（バッジ）
- あなたへの通知・チャージは、本人宛ての未読のうち作成から31日以内のものを件数として数える。
- お知らせは、現在表示中（公開済み・表示終了前）のお知らせのうち、本人がまだ閲覧していないものを件数として数える。
- バッジ件数は上記の合算とする。アクセス頻度が高い場合は、件数のキャッシュ併用も検討可（お知らせ分は都度集計）。

### 5-2. 保持期間・パージ
| 対象 | 保持 | 処理 |
|------|------|------|
| あなたへの通知 / チャージ | 31日 | 日次バッチで31日を超えたものを削除する |
| お知らせ | 長期 | 削除しない。表示終了日時で表示を制御する。過去のお知らせの既読情報も保持する |

- 一覧表示でも「作成から31日以内」の条件を適用し、パージ前でも31日を超えたものは表示しない。
- ※ お知らせの保持方針は §9-B で要承認。

## 6. 画面要件（フロント）

| 区分 | 要件 |
|------|------|
| ベル | ヘッダー右上。未読件数を画面表示時/タブ復帰時に取得。未読 > 0 で赤丸＋件数 |
| タブ | あなたへの通知 / チャージ / お知らせ。アクティブはゴールド下線。タブ見出しに未読小バッジ |
| リスト | 行 = 日時（薄字 `YYYY年M月D日 HH:mm`）＋本文。未読は強調（太字/左ドット） |
| お知らせ行 | 右端 `>`、タップで詳細ページへ＋既読化 |
| ページャ | 1ページ20件、番号ページャ |
| 空状態 | 「通知がありません」 |
| 既読化 | 行タップ時に既読化し、楽観的UI更新→バッジ再取得 |

## 7. 非機能要件

| 区分 | 要件 |
|------|------|
| 性能 | 一覧/未読件数の取得は p95 < 300ms を目標とする |
| スケール | お知らせは全ユーザー分を行展開しない（既読のみ別管理）。セグメント個別送信は非同期バッチ/キューで処理する |
| セキュリティ | personal/charge は本人のみ参照（サーバ側で認可）。管理機能は管理者ロール必須 |
| 整合性 | 通知生成は業務処理の成功後に行う。生成失敗時は業務本体を巻き戻さずログ＋リトライ |
| 監査 | 管理配信・個別送信は操作者と日時を記録する |
| i18n | 本文はテンプレート＋差込方式とし、将来の多言語化に備える |

## 8. 受け入れ基準（抜粋 / Given-When-Then）

- AC-01: 未読がある状態でアプリを開くと、ベルに赤丸と未読件数（3タブ合算）が表示される。
- AC-02: ベル押下で通知ページの「あなたへの通知」が開く。
- AC-03: タブ切替で各リストが正しく切り替わり、新しい順に表示される。
- AC-04: 発送ステータスを「発送済」に更新すると、対象ユーザーのあなたへの通知に配送通知が1件増える。
- AC-05: ランクアップ通知に新ランク・獲得ポイント・還元率(%)が本文に含まれる。
- AC-06: 決済完了でチャージタブに「…コイン(…ランクポイント)をチャージしました」が増える。
- AC-07: お知らせ行の `>` で詳細ページに遷移し、当該お知らせが既読になる。
- AC-08: 「すべて既読にする」でそのタブの未読が0になり、バッジが減算される。
- AC-09: 他ユーザーのpersonal/charge通知はAPI/画面で取得できない（403/除外）。
- AC-10: 作成31日経過のpersonal/charge通知が一覧・バッジから除外され、バッチで削除される。
- AC-11: 管理画面からお知らせを即時/予約配信でき、全ユーザーのお知らせに反映される。
- AC-12: 管理画面から個別ユーザーに任意テキストの個別お知らせを送信できる。

## 9. 未確定事項（実装前に要確認）

| # | 確認点 | 影響 | 暫定 |
|---|--------|------|------|
| A | 実スタック（DB/認証/フレームワーク）の確認 | データ設計・認可・API実装方式 | 実装時に確定 |
| B | お知らせ（broadcast）の保持期間 | パージ範囲 | 長期保持（削除しない）を推奨 |
| C | チャージタブに含める範囲 | charge通知の種類 | 課金完了明細のみ。ボーナス等は要相談 |
| D | コインに有効期限があるか | `coin_expiry` 要否 | あれば有効化、無ければ削除 |
| E | ベル設置位置 | UI | グローバルヘッダー右上（全ページ） |
| F | セグメント定義（ゴールド会員等）の有無 | 個別送信の宛先 | 既存ランク/属性を流用想定。**絞り込み条件＝ガチャID利用者／直近ログインN日以内** を標準提供 |
| H | 「ガチャ利用」の定義（抽選実行=利用 / 特定ランク当選 等） | ガチャID絞り込みの対象範囲 | 「抽選を実行した」を既定。当選ランク条件が必要なら追加 |
| G | リアルタイム性（即時反映 vs ポーリング） | 配信方式 | 画面表示時取得（ポーリング）で開始 |
