# 要件定義書｜対抗戦（レイドイベント）

> クライアント共有用。**設計・実装方式（DB/API等）は含めません**（実装担当が設計）。
> 構成: ①想定している挙動 ②重要キーファンクション（必達） ③補完要件（イレギュラー対応） ④デザイン要件（mockで確認）

| 機能ID | クライアント | 対象画面（stg実機） |
|--------|------------|---------------------|
| 01-d | ノヴァガチャ様 | イベントスペース（現「バッテリー交換所」を拡張）内の対抗戦ページ |

---

## ① 想定している挙動

全ユーザー共有の**ボス**に、**コインを消費して攻撃しHPを削る**対抗戦（レイド）。
全体でボスを**討伐**すると、**自分の貢献度に応じて「高還元ガチャ」を回せる**ようになる（救済・ご褒美）。

**想定シーン**
1. イベントスペースに「対抗戦」開催。ボスとHPバーが表示される。
2. ユーザーがコインを消費して攻撃 → **消費コインに応じてボスHPが減る**。
3. 攻撃するほど**自分の貢献度（与ダメージ累計）**が貯まる。ランキングで順位も見える。
4. 全体でHPが0＝**討伐成功**。
5. 討伐時、**貢献度（ティア）に応じて高還元ガチャを回せる回数**が付与される。
6. ユーザーはその高還元ガチャをコインで回して報酬を得る。

---

## ② 重要キーファンクション（必達）

- **コイン消費に応じてボスHPが減る**こと（消費量＝ダメージの関係が一貫）。
- **貢献度（与ダメージ累計）をユーザー別に正確に記録**すること。
- ボスHPは **全ユーザー共有**で、合算ダメージで減ること。
- HPが0で **討伐が確定**し、以降は攻撃を受け付けないこと。
- 討伐時、**貢献度（ティア）に応じて高還元ガチャを回せる回数**が付与されること。
- **イベント期間内のみ**参加できること。

---

## ③ 補完要件（イレギュラー対応）

| 想定シーン | あるべき挙動 |
|-----------|-------------|
| 残りHPわずかで複数人が同時に攻撃 | **HPはマイナスにならない**。超過ダメージは無効、**討伐確定は1回だけ** |
| 攻撃の連打・二重送信 | 貢献度を**多重カウントしない**（消費1回＝加算1回） |
| コイン残高不足で攻撃 | 攻撃不可（不足が分かる表示）。HP・貢献度は変えない |
| 期間内に討伐できず終了 | 未討伐時の扱いを定義（参加賞 or 報酬なし）※**要確認** |
| 討伐後、解放回数を使い切り | 高還元ガチャは回せない（回数0で打ち切り） |
| 期間外・終了後にアクセス | 「開催前／終了」を表示し、攻撃不可 |
| 解放された高還元ガチャの権利 | **ユーザー×イベント単位**で管理（他イベントに持ち越さない） |

## ④ デザイン要件（mockで確認）

- 設置場所は **イベントスペース**（現「バッテリー交換所」を拡張したハブ）内の対抗戦ページ。
- 画面要素: **ボスビジュアル＋HPバー（全体進捗）／自分の貢献度・ティア／貢献ランキング／攻撃導線／討伐演出 → 高還元ガチャ解放**。
- 高還元ガチャの解放表示は、**BT解放（01-b）と同じ「解放ブロック」の考え方**を流用（回数つき）。
- 実機のダークネオンUI・トークンに準拠。

**確認用mock**

- 管理画面制御: [管理画面制御.html](../../mocks/争奪戦/対抗戦レイド/管理画面制御.html)（ボス・ダメージ係数・貢献ティア・報酬ガチャ）

## 要確認（クライアント）
- 攻撃手段: **専用ガチャを回す＝攻撃（景品も出る）** を推奨。直接攻撃（コイン消費のみ）も可。
- 未討伐終了時の報酬（参加賞の有無）。
- ボスのマルチステージ／周回の有無。
- 「対抗戦」をチーム対抗（紅白の山分け等）に発展させるか（→ イベント基盤のチーム戦として拡張可能）。
