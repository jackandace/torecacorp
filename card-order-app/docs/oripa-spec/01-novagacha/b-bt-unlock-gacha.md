## 1. 目的・お客様がやりたいこと

特定のガチャに **「BTロック」** をかけ、**BTを指定数消費することでそのガチャを解放** できるようにしたい。
解放後はコインで通常通りガチャを回せる。

> **還元率100%OVER** のような特別なガチャへのアクセス制御として使いたい。
> （他社でいうイベントチケット的なイメージ）

**利用イメージ:**
```
BT 10個を消費  →  還元率100%OVERガチャが解放  →  以降コインで回せる
```

---

## 2. 重要な仕様要件

### 2-1. 解放条件
- 消費するBT数は **管理画面でガチャごとに設定** できること。
- BTが不足している場合は **解放不可（エラー表示）**。

### 2-2. 解放の単位
- **ユーザーごと × ガチャごと** に解放状態を管理する。
- 一度解放したら以降はコインで回せる（**永続**）。

### 2-3. ユーザー画面
- ロック中のガチャは「**BT ○個で解放**」とわかる表示にする。
- 解放ボタン → 確認ダイアログ（「**BT ○個を使用しますか？**」）→ 確定でBT消費・解放。

### 2-4. 管理画面
- ガチャ作成・編集画面に **BTロックの ON/OFF 設定** を追加。
- **消費BT数を数値で設定** できること。

## 4. 解放判定ロジック

ユーザーが対象ガチャにアクセスした際の状態判定:

- ガチャがBTロック無効なら、常に解放状態（ロックなし）として扱う。
- BTロック有効で、そのユーザーの解放記録が無ければロック状態とする。
- 解放記録があり、（将来拡張の）有効期限が設定されていて期限切れの場合はロック状態に戻す。それ以外は解放状態とする。

- ロック状態の間はガチャ抽選・抽選ボタンを **不可** にする（コイン消費もさせない）。
- 解放状態になれば 01-a / 通常ガチャと同じ抽選フローへ。

---

## 5. 解放処理

ユーザーが解放を実行した際のサーバ処理（トランザクション内で一貫処理）:

1. 対象ガチャがBTロック対象でなければエラー（通常はUIで到達しない）。
2. 既に解放済みなら、二重消費せずそのまま解放成功として扱う（冪等）。
3. BT残高が解放に必要なBT数に満たなければBT不足エラー（必要数・保有数を返す）。
4. 必要なBT数を消費し、BT取引ログに解放理由で記録する。
5. 解放記録を作成する。同時押下・再送でも二重に作成されないようにする。
6. 解放成功（消費BT数・消費後残高）を返す。

**冪等性**: 同時押下・再送に対し、解放記録の一意性チェックで二重消費を防止する。

---

## 6. 管理画面（コンソール）

ガチャ作成・編集画面に「BTロック」セクションを追加。

```
┌─ BTロック設定 ─────────────────────────────┐
│ BTロック        [ ●ON / ○OFF ]  ← トグル        │
│ 解放に必要なBT数 [   10   ] BT                  │
│   ※ロック中のガチャはコインで回せません。         │
│     ユーザーがBTを消費して解放すると以降コイン可。  │
└────────────────────────────────────────────┘
```

- BTロック=ON のとき「解放に必要なBT数」を必須・1以上で入力。
- 一覧画面でロック付きガチャに「🔒 BT解放」バッジを表示。
- （任意拡張）解放ユーザー数の表示で人気度を把握できると運用に有用。

---

## 7. ユーザー画面

### 7-1. ロック中の表示
ガチャカード／詳細に錠前と解放コストを表示。

```
┌────────────────────────┐
│   [ ガチャ画像 ]   🔒    │
│   還元率100%OVER ガチャ  │
│  ┌──────────────────┐   │
│  │ 🔒 BT 10個で解放    │   │  ← ロック表示
│  └──────────────────┘   │
│   [  🔋 BTで解放する  ]   │  ← 解放ボタン
└────────────────────────┘
```

### 7-2. 解放確認ダイアログ
```
┌──────────────────────────────┐
│  このガチャを解放しますか？        │
│                                │
│  🔋 BT 10個 を使用します          │
│  保有BT: 24 → 14                │
│                                │
│  [ キャンセル ]   [ 解放する ]    │
└──────────────────────────────┘
```

### 7-3. 解放後
- 錠前・解放ボタンが消え、通常の抽選ボタン（コイン消費）に切り替わる。
- 「✅ 解放済み」バッジを表示（再解放は不要・不可）。

### 7-4. BT不足時
- 解放ボタン押下 → ダイアログ内で「BTが不足しています（保有 4 / 必要 10）」を表示し確定不可。
- BT入手導線（BTドロップ対象ガチャ等）への動線があると親切（任意）。

## 8. エラーハンドリング

| ケース | ユーザー表示 |
|--------|--------------|
| BT不足 | 「BTが不足しています（保有 X / 必要 Y）」 |
| 既に解放済み | そのまま抽選画面へ（冪等） |
| ロック対象外ガチャ | （通常は到達しない／UIで非表示） |
| 二重リクエスト | 二重消費なし。1回分のみ |

---

## 9. テスト観点

- [ ] BTロックON設定で、未解放ユーザーは抽選不可・ロック表示
- [ ] 解放ボタン → 確認ダイアログ → 確定でBTが正しく消費され解放
- [ ] 解放後はコインで通常抽選できる
- [ ] 解放状態がユーザー×ガチャ単位で永続（再ログイン後も維持）
- [ ] BT不足時に解放不可・不足数を表示
- [ ] 解放ボタン連打・API再送で二重消費しない（冪等）
- [ ] BTロックOFFのガチャは従来通り（解放不要）
- [ ] BT取引ログに解放分の消費が記録される

## 10. 将来拡張メモ
