# 01-a. 課金消費型ガチャの BT消費ガチャ対応

| 項目 | 内容 |
|------|------|
| クライアント | ノヴァガチャ様 |
| 機能ID | 01-a |
| 工数目安 | 3D（人日） |
| 種別 | 既存「課金消費型ガチャ」の拡張 |
| ステータス | 仕様確定待ち |

---

## 1. 目的・背景

現在の **課金消費型ガチャ**（＝課金限定ガチャ）は、
「設定課金額を満たすと1回引く権利が付与され、**設定した消費コイン**でガチャを回せる」
という仕様になっている。

本対応では、ガチャを回す際の **消費リソースを「コイン」だけでなく「BT（バッテリー）」でも設定できる**ように拡張する。
これにより、BTを貯めたユーザー向けの課金消費ガチャを運用可能にする。

> 添付キャプチャの設定画面（オリパタイプ: 課金消費 / 消費量 / 1回あたりの必要課金額 …）が対象画面。

---

## 2. 現行仕様（おさらい）

課金消費型ガチャの抽選フロー（現行）:

```
① ユーザーが対象ガチャ公開後に課金する
② 累計課金額 ÷ 「1回あたりの必要課金額(円)」= 獲得した抽選権数
③ 抽選権がある状態で、「消費量(コイン)」を支払ってガチャを1回実行
④ 上限回数（任意）に達すると以降は実行不可
```

現行の設定項目（キャプチャ準拠）:

| 設定項目 | 説明 |
|----------|------|
| オリパタイプ | 通常 / ポイント / バッテリー / 課金消費 |
| 消費量 | 1回の抽選で消費する数量（現状コイン） |
| 1回あたりの必要課金額（円） | この額を課金するごとに抽選権を1つ付与 |
| 上限回数（任意） | 空欄で無制限 |
| ガチャ条件 | 条件無し 等 |
| ガチャ回数設定 | 1回 / 10連 / 100連 の選択可否 |
| レベル制限 | 利用可能ユーザーのレベル制限 |
| 通常バッテリードロップ率 | 抽選結果に応じたBTドロップ率(%) |

---

## 3. 本対応の要件

### 3-1. 機能要件

1. 課金消費型ガチャに **「消費リソース」設定** を追加する。
   - 選択肢: **コイン** / **BT（バッテリー）**
   - デフォルト: コイン（既存ガチャの挙動を変えない＝後方互換）
2. 「消費リソース = BT」を選択した場合、「消費量」は **1回の抽選で消費するBT数** を意味する。
3. 抽選実行時、ユーザーの保有BTが消費量に満たない場合は **抽選不可（エラー表示）**。
4. 連続抽選（10連 / 100連）時は **消費量 × 回数** のBTをまとめて消費する。
5. 抽選権の付与ロジック（課金額ベース）は **現行から変更しない**。
   - 「BTを消費する」≠「BTで抽選権を買う」。あくまで **課金で権利を得て、BTで回す** 構造。

### 3-2. 非機能・互換要件

- 既存の課金消費型ガチャ（消費リソース未設定）は **コイン消費として動作** する（マイグレーション時に `coin` を既定値で付与）。
- BT残高の増減は既存のBTウォレット／取引履歴の仕組みに記録する（消費理由 = `gacha_paid`）。

---

## 4. 管理画面（コンソール）

オリパ作成・編集画面、「オリパタイプ = 課金消費」を選択した際に、以下を追加表示する。

```
┌─ ガチャ設定（課金消費）────────────────────┐
│ 消費リソース   ( ● コイン  ○ BT(バッテリー) )      │  ← 新規ラジオ
│ 消費量         [ 10000 ]                          │  ← ラベル文言が
│                 ※BT選択時は「消費BT数」と表示       │     リソースに応じ動的
│ 1回あたりの必要課金額（円） [ 1000 ]               │
│ 上限回数（任意） [ 無制限 ]                         │
└────────────────────────────────────────────┘
```

- 「消費リソース」を **BT** に切り替えると、消費量のラベル／プレースホルダ／単位表示を「BT」に動的変更。
- バリデーション: 消費量は 1 以上の整数。

---

## 5. ユーザー画面

ガチャ詳細・抽選ボタン周辺の表示を消費リソースに応じて切り替える。

| 状態 | 表示 |
|------|------|
| コイン消費 | 「🪙 10,000 コインで回す」 |
| BT消費 | 「🔋 5 BTで回す」 |
| BT残高不足 | ボタン非活性 + 「BTが不足しています（保有: 2 / 必要: 5）」 |

抽選確定後、結果モーダルにBT消費内訳（消費 5BT / 残高 12BT）を表示。

---

## 6. エラーハンドリング

| ケース | 挙動 |
|--------|------|
| BT残高不足 | ユーザーへ不足数を明示 |
| 抽選権なし（課金不足） | 現行と同様 |
| 上限回数到達 | 現行と同様 |
| 連続抽選途中で残高不足 | 抽選前にまとめて検証するため部分消費は発生しない |

---

## 7. テスト観点

- [ ] 消費リソース=コインの既存ガチャが従来通り動作（後方互換）
- [ ] 消費リソース=BTでガチャを1回／10連／100連実行しBTが正しく減算
- [ ] BT残高不足時にボタン非活性・エラー表示
- [ ] 課金額に応じた抽選権付与はリソース種別に依存しない
- [ ] BT取引ログに `gacha_paid` が記録される
- [ ] 管理画面でリソース切替時にラベルが動的変更される
