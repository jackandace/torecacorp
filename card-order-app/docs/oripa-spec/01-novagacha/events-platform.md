## 0. 依頼背景（Yu.様）

> 「バッテリー交換所を **イベントスペース** にして、**福袋争奪戦イベント／チーム戦イベント** など大型アップデートをしたい。
> **レイドイベント**もできますか？ 消費コイン数に応じてボスHPを削って、倒したら貢献度によって高還元ガチャを回せる感じ。
> **イベントページ**が必要になります。」

→ 単発機能ではなく、**複数のイベント種別を載せられる共通基盤（イベントスペース）** として設計する。
個別イベントは本基盤の上に「イベント種別（type）」として実装する。

---

## 1. 全体構成

```
イベントスペース（旧:バッテリー交換所を拡張）
├─ 開催中イベント一覧（バナー）
│   ├─ 福袋争奪戦      … ランキングイベント   → 01-c
│   ├─ レイドイベント   … 討伐型イベント       → 01-d
│   ├─ チーム戦         … チーム対抗（今後）   → §6
│   └─ （随時追加可能）
├─ 各イベントの「イベントページ」（詳細・参加・進捗・報酬）
└─ バッテリー交換所（既存機能は内包して継続）
```

- **イベントスペース** をアプリの常設エントリ（ナビ/ホーム導線）に設置。
- 開催中/予告/終了をステータスで出し分け、バナーから各 **イベントページ** へ遷移。

---

## 2. 共通仕様

### 2-1. イベント種別（type）
| type | 名称 | 概要 | 仕様書 |
|------|------|------|--------|
| `ranking` | ランキングイベント（福袋争奪戦） | 期間中のポイント順位で報酬 | [c-event-fukubukuro.md](c-event-fukubukuro.md) |
| `raid` | レイドイベント | 全体でボスHPを削り、討伐で貢献度報酬 | [d-event-raid.md](d-event-raid.md) |
| `team_battle` | チーム戦 | チーム対抗（今後・§6） | （別途） |
| `exchange` | 交換所 | 既存バッテリー交換所 | （既存） |

### 2-2. ステータス遷移
```
draft → scheduled →(starts_at)→ active →(ends_at)→ ended →(集計/報酬付与)→ closed
```
- `active` 中のみユーザーが参加・進捗加算可能。
- `ended` で受付停止、ランキング確定・報酬付与処理 → `closed`。

### 2-3. 通知連携（02-a と連携可）
- 報酬付与時に「あなたへの通知」へ自動送信（イベント報酬を付与しました 等）。
- ※NOVAはGRIM(02-a)とは別プロダクトのため、NOVA側通知基盤の有無に応じて実装。

### 2-4. 管理画面（共通）
- イベント一覧（種別/期間/ステータス）、新規作成、バナー設定、公開/終了操作。
- 種別ごとに専用設定タブ（ポイント配分・報酬・ボスHP 等）。
- 集計結果・報酬付与履歴の確認。

---

## 3. ユーザー画面（共通）

- **イベントスペース トップ**: 開催中/予告のイベントバナー一覧。
- **イベントページ**: 各イベントの詳細（ルール）・自分の進捗・ランキング/HP・報酬一覧・参加導線。

---

## 4. 「バッテリー交換所 → イベントスペース」移行方針

| 観点 | 方針 |
|------|------|
| 既存交換所 | 機能は維持し、イベントスペース内の1メニュー（`exchange`）として内包 |
| 導線 | ナビ名称を「イベント」または「イベントスペース」に変更（交換所はその中） |
| 互換 | 既存のBT交換ロジック・在庫はそのまま流用 |

> ※ 名称変更・導線位置は要確認（§7-A）。

---

## 5. レイドイベント実現可否

**可能です。** 詳細は [d-event-raid.md](d-event-raid.md)。
- 消費コインに応じてボスHPを削る → 討伐時に貢献度に応じて **高還元ガチャ** を解放（既存 01-b BTロック解放の「アクセス制御」を貢献度ベースに応用）。

---

## 6. チーム戦イベント（今後・概要のみ）

- ユーザーを **チーム** に所属させ、チーム合算スコアで対抗。
- スコア源は ranking と同様（賞獲得pt・課金pt 等）＋チーム貢献ボーナス。
- 報酬: チーム順位報酬＋個人貢献報酬。
- データ: `teams`, `team_members`, チーム集計。
- → 要望確定後に個別仕様化（本基盤の `team_battle` type を使用）。
