# 設計: 卸アプリ運用以前の購入履歴 (legacy purchases)

ステータス: **実装済み (2026-09-30)** — 購入履歴・一括取込・過去請求書の紐付け

## 目的

卸アプリ導入前から取引のあるショップ(パチパチトレカ様など)について、
アプリ以前の購入実績を管理画面に登録し、管理側とショップ側(マイページ)の双方で
「いつ・何を・何個・いくらで購入したか」「出荷済みかどうか」を確認できるようにする。

## スコープ

| 対象 | 扱い |
|---|---|
| 商品名・数量・単価・購入金額・購入日 | 登録する |
| 出荷可否(出荷済 / 未出荷) | 登録する(アプリ以前の未出荷分があるため) |
| 入金日・入金状況 | 扱わない(購入金額が分かればよい) |
| 追跡番号・発送日 | 扱わない |
| 当時の請求書 PDF のダウンロード | 扱わない(既存の「過去請求書 (legacy)」機能は別途そのまま) |

## 基本方針: 既存の発注 (orders) とは別テーブルにする

アプリの発注 (orders) に混ぜると、次の計算に過去分が紛れ込んで壊れるため、専用テーブルに分離する。

- 月次ランク判定・リベート計算
- 請求書発行(請求対象の発注一覧)
- 在庫の発注済数 (products.ordered_qty)
- レポート・売上予測・ダッシュボード KPI

過去分は「参照用の記録」であり、これらの計算には一切入らない。
既存の累計取引額 (shops.lifetime_amount・ランクの最低保証に使用) とも自動連動はしない(→ 決定事項 D)。

## データ設計

新テーブル `legacy_purchases`(マイグレーション 034 で追加予定)

| カラム | 型 | 必須 | 内容 |
|---|---|---|---|
| id | uuid | ○ | |
| shop_id | uuid → shops | ○ | どのショップの履歴か |
| purchased_on | date | ○ | 購入日 |
| product_name | text | ○ | 商品名(アプリの商品マスタとは紐付けない自由入力) |
| quantity | integer | ○ | 数量 |
| unit | text | ○ | 単位(BOX / CT など。既定 BOX) |
| unit_price | integer | ○ | 単価(円) |
| amount | integer | ○ | 購入金額(円)。既定は 数量×単価 を自動計算、値引き等で手修正も可 |
| shipment_status | text | ○ | `shipped`(出荷済)/ `unshipped`(未出荷) |
| note | text | | 備考(社内メモではなくショップにも見える点に注意) |
| created_by / updated_by | uuid | | 登録・更新した管理者 |
| created_at / updated_at | timestamptz | ○ | |
| deleted_at | timestamptz | | 論理削除(誤登録の取り消し用) |

- 権限 (RLS): 管理者は全操作可。ショップは**自分の行の閲覧のみ**(`shop_id` が自分のショップ、かつ未削除)
- 登録・編集・削除は監査ログに記録

## 画面設計

### 管理画面(顧客管理 → ショップ詳細)

- ショップ詳細に「**購入履歴(アプリ運用以前)**」セクションを追加
- 一覧: 購入日 / 商品名 / 数量 / 単価 / 金額 / 出荷状況 / 操作(編集・削除)
- 絞り込み: 購入日の期間・商品名検索、ページ送り
- 「+ 購入履歴を追加」でフォーム(商品名・数量・単位・単価・金額[自動計算]・購入日・出荷状況・備考)
- 集計表示: 登録件数・合計金額・未出荷件数
- 未出荷の行は目立つ表示にし、出荷したら編集で「出荷済」に切り替える

### ショップ側(マイページ)

- マイページに「**購入履歴(アプリ運用以前)**」を追加(既存の「発注履歴」「請求書」とは別枠)
- 表示: 購入日 / 商品名 / 数量 / 単価 / 金額 / 出荷状況。閲覧のみ
- 期間・商品名で絞り込み、スマホはカード表示
- 登録が 0 件のショップには表示しない

## 段階リリース案

| 段階 | 内容 | 目安 |
|---|---|---|
| 第1段階 | テーブル追加・管理画面での1件ずつ登録/編集/削除・マイページ表示 | 1日程度 |
| 第2段階(任意) | Excel / CSV 一括取込(過去の発送管理表などから流し込む) | 半日程度 |

件数が多いショップ(数十件以上)が複数あるなら、第2段階を早めに入れた方が入力作業は大幅に楽になる。

## 決定事項 (2026-09-30)

| | 決定 |
|---|---|
| A. 金額 | **税抜**で統一 |
| B. 未出荷→出荷時の通知 | **通知しない** (管理画面で切り替えるだけ) |
| C. 登録方法 | 手入力 + **テンプレート形式の一括取込** (見出し完全一致・1行でもエラーなら登録しない・取込単位で取り消し可) |
| D. 累計取引額 | **連動しない** (累計は金額だけ反映済み。購入履歴はあくまで参照用) |
| E. 備考 | お客様に見える「備考」と非表示の「社内メモ」を分ける |

## 一括取込の仕様 (データのブレ対策)

- テンプレートは管理画面の購入履歴ページから Excel をダウンロード (列定義はコードと共通なので取込とずれない)
- 入力シート「購入履歴」は見出しのみ。記入例は別シート (例が取り込まれる事故を防ぐ)
- **見出し行がテンプレと完全一致しないファイルは拒否** (列の追加・並べ替え・書き換えを検出)
- 取込は2段階: 「内容を確認」で全行の解釈結果・エラー・警告を表示 → エラー0件のときだけ「この内容で登録」
- エラー: 日付が読めない/未来日、数量・単価が整数でない、単位・出荷状況が選択肢外、商品名が空 など
- 警告 (登録は可能): 金額が 数量×単価 と不一致、ファイル内の重複行、既に登録済みと同じ内容 (二重取込)
- 取込ごとに `import_batch_id` を付与し、「取込履歴」から**その取込をまとめて取り消せる**
- 1回あたり最大 1,000 行・5MB

## 請求書アップと紐付け (2026-09-30 実装)

決定: 請求書1枚に複数の購入履歴行を紐付ける。お客様には既存の「請求書」一覧に加え、購入履歴の行からもリンクする。

- アップロードは既存の「過去請求書」機能 (invoices.is_legacy・PDF は legacy-invoices バケット) を購入履歴ページからも使えるようにした
- 行を選んで請求書に紐付け / 解除 (`POST /api/shops/[id]/legacy-purchases/link`)
- **誤紐付けの防止**: 紐付け API が「同じショップの」「過去請求書」「未削除」であることと、対象行がすべて同じショップの行であることを検証。
  マイページも同条件で絞り込んだ請求書だけリンクを出し、ダウンロード API も本人確認する (3重)。
  起こりうる誤りは「同じお客様の別の請求書に付けてしまう」ことだけで、請求書ごとの紐付け件数・合計と請求書金額の見比べで気付ける
- **既存不具合の修正**: 過去請求書の「PDFを開く」が、アップした PDF ではなく請求データから作り直した PDF を返し、
  pdf_url を上書きしていた。過去請求書はアップ済み PDF を返すよう修正し、再生成 API は過去請求書を拒否する。
  上書きで元のパスを失った請求書も、バケット内を請求書番号で探して元 PDF を返す。
  アップロード時は 1年で切れる署名 URL ではなく保存パスを記録するよう変更
